# 归档机器人 - 管理员命令手册
## 简介
> 本文档详细描述了归档机器人的管理员命令。这些命令通过Discord的斜杠命令接口提供，用于对机器人的核心功能进行运行时配置。所有命令均以 `/admin` 作为根命令。
### 权限模型
> 所有 `/admin` 子命令的执行权限均受到严格控制。操作发起者必须拥有在配置文件 `appsettings.jsonc` 的 `AuthConfig.AdminRoleIds` 数组中定义的任一身份组ID。若权限不足，命令将执行失败并返回权限错误提示。
## 命令详解
### 1. 添加服务器配置 (`/admin add-guild`)
> 此命令用于将一个新的服务器纳入机器人的自动归档管理范围。
> - 功能描述:
>   在系统的配置中为指定服务器创建一条新的归档规则。
> - 执行前提:
>   1.  机器人必须已作为成员加入目标服务器。
>   2.  目标服务器的配置在系统中必须尚不存在。
> - 参数:
>   - `guild-id` (字符串, 必需): 目标服务器的 Snowflake ID
>   - `limit` (整数, 必需): 为该服务器设定的活跃线程数量阈值。此值界定了在自动归档时服务器可保持的活跃线程的最大数量。有效范围为 `900` 至 `999`。
> - 使用示例:
```
/admin add-guild guild-id:123456789012345678 limit:970
```
> - 执行结果:
>   - 成功: 返回操作成功的确认信息，并包含目标服务器的名称、ID以及新设定的 `limit` 值。配置将被持久化。
>   - 失败:
>     - 若机器人不是目标服务器的成员，操作将被拒绝，并返回相应错误信息。
>     - 若配置已存在或 `limit` 参数超出有效范围，操作将失败，并提示用户检查输入或系统日志。
### 2. 修改当前服务器上限 (`/admin set-limit`)
> 此命令允许管理员快速调整当前服务器的活跃线程上限。
> - 功能描述:
>   更新执行命令所在服务器的活跃线程数量阈值。
> - 执行前提:
>   - 当前服务器必须已通过 `/admin add-guild` 命令进行过配置。
> - 参数:
>   - `limit` (整数, 必需): 新的活跃线程数量阈值。有效范围为 `900` 至 `999`。
> - 使用示例:
```
/admin set-limit limit:980
```
> - 执行结果:
>   - 成功: 返回操作成功的确认信息，并显示新的 `limit` 值。配置将被持久化。
>   - 失败:
>     - 若当前服务器未被配置，操作将失败，并提示需要先添加配置。
>     - 若 `limit` 参数超出有效范围，操作将失败。
### 3. 修改归档任务间隔 (`/admin set-interval`)
> 此命令用于调整后台归档任务的执行频率。
> - 功能描述:
>   修改全局定时归档任务的执行周期。
> - 参数:
>   - `minutes` (整数, 必需): 新的执行间隔，单位为分钟。此值必须大于 `0`。
> - 使用示例:
```
/admin set-interval minutes:5
```
> - 执行结果:
>   - 成功: 返回操作成功的确认信息，并显示新的间隔时间。后台定时器将根据新值重置。配置将被持久化。
>   - 失败:
>     - 若 `minutes` 参数小于或等于 `0`，操作将失败。
### 4. 重新加载配置文件 (`/admin reload-config`)
> 此命令用于从外部文件系统热加载配置文件，以应用带外修改。
> - 功能描述:
>   触发系统从磁盘上的 `appsettings.jsonc` 文件重新读取并应用所有配置。此操作无需重启服务。
> - 安全机制:
>   - 在加载过程中，系统将对新配置文件的内容进行完整性与有效性验证。如果新配置未能通过验证（例如，JSON格式错误或配置值不合法），加载过程将被中止，系统将继续沿用当前内存中的有效配置，以保证服务的连续性和稳定性。详细的错误信息将被记录到系统日志中。
> - 参数: 无
> - 使用示例:
```
/admin reload-config
```
> - 执行结果:
>   - 返回一个操作已执行的通知。操作的最终结果（成功应用新配置或保留旧配置）应通过查阅系统控制台或文件日志来确认。
